# 映汐放映站 0.2.0-alpha.40 / Yingxi 0.2.0-alpha.40

## 中文

【拾荒者信笺】

阿汐把同一只片匣的纸条夹好。迟灯翻查时，不用每翻一页就回登记台问一次。

【本次修缮】

1. 阿里云盘续播与定位时，复用当前播放会话的文件信息和下载地址；地址失效后重新申请，分段内容仍逐次校验。
2. 下载请求复用客户端与连接池，减少影片重开时重复建立下载连接的开销。
3. 连续播放沿用同一条分段响应，不再由本地每隔 8 MiB 重开请求；拖动时按新位置接续。
4. 检修记录区分取得播放地址、等待片源响应和读取数据，补充分段请求、源读取字节数与各阶段等待，长时间转圈时可以查看和复制。

同一只片匣，纸条夹在一起。别翻一页，就重抄一遍。——阿汐

## English

[Scavenger's letter]

Axi has clipped the slips for each film case together. Chideng no longer has to return to the desk with every page he turns.

[Repairs this time]

1. Aliyun Drive reuses file information and the download address within the current playback session when resuming or seeking. Rejected addresses are renewed, and every range response remains validated.
2. Downloads share a client and connection pool, reducing repeated connection setup when a film is reopened.
3. Sequential playback keeps the same range response instead of reopening every 8 MiB. Seeking starts a response at the new position.
4. Repair records separate obtaining an address, waiting for a source response and reading data. They include range requests, source bytes and stage waits, ready to view and copy during a long playback wait.

> Keep the slips for one film case together. Turning a page should not mean copying them all again. — Axi
