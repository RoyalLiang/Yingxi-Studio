# 开始工作

目标是用最少上下文找到当前事实、改动边界和验证方法。此文只负责阅读顺序，项目指令仍由实际的 `AGENTS.md` 与 `.agents/` 决定。

## 先冻结本次基线

```sh
git status --short --branch
git rev-parse HEAD
git worktree list --porcelain
cat version.json
```

在本地有 `.agent-runtime/state-lite.json` 时先读摘要，再按主题与游标读取必要证据。记录是恢复线索；分支、发布、设备安装状态都要以当前拥有者核对。

需要远端状态时刷新分支，保留已有标签：

```sh
git fetch --no-tags origin --prune
```

标签冲突应单独记录和核对，不覆盖已发布标签，不把旧工作树的标签当成远端公开版本。

## 按问题扩展上下文

1. 问“现在有什么”：读[当前版本](current.md)和[能力总表](capabilities.md)。
2. 问“代码在哪里”：读[架构与代码地图](architecture.md)中对应一行，再读调用方与测试。
3. 要实施或合并：列出会触及的调用方、持久化、测试、配置与生成物，然后按[验证与交付](validation.md)检查。
4. 涉及某个旧修复：从[历史证据](../history/README.md)进入精确版本，别把旧候选报告升级为当前结论。
5. 要改文档：按[维护文档](documents.md)更新拥有者和目录，避免增加一份内容相同的状态说明。

## 一次任务只保留这些信息

目标、阶段、约束、当前基线、已确认发现、改动文件、验证结果、下一步、证据路径。不要将完整日志、私人草稿、账户、媒体地址或签名材料复制进公开文档。

遇到叙述冲突，分别回答：要求是什么、源码实现了什么、哪一版在哪种环境验证、远端实际发布了什么。证据不能互相替代。

文档索引见[上一级入口](../README.md)，机器选择条件见[目录数据](../catalog.json)。
