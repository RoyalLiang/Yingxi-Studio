# 维护文档

公开文档目录由 [`catalog.json`](../catalog.json)描述，阅读入口为 [docs/README.md](../README.md)。文档跟随功能拥有者，只有一份当前摘要；其他页面链接到它。

## 四层阅读约定

| 层级 | 用途 | 加载条件 |
| --- | --- | --- |
| L0 | 入口、基线核对与任务路由 | 每次开始任务，先读最小入口 |
| L1 | 当前版本、能力、架构与验证摘要 | 只读与任务匹配的摘要 |
| L2 | 功能专题、工程规则与数据拥有者 | 摘要不足或即将修改相应范围 |
| L3 | 精确版本报告与信笺 | 查历史、回归归因或固定版本证据 |

目录字段 `kind` 区分 `entry`、`current`、`reference`、`decision`、`generated`、`historical` 与 `release`。`loadWhen` 是读取条件。目录不是执行授权，也不能覆盖项目规则。

## 按拥有者解决重复与冲突

| 内容 | 权威来源 | 派生物或说明 |
| --- | --- | --- |
| 当前安装版本 | `version.json` | 当前状态页只保存带日期的核对快照 |
| 实现行为 | 对应提交的源码 | 能力总表与专题说明 |
| 验证结论 | 精确提交、环境、命令和结果 | 历史报告仅对原范围有效 |
| 公开发布 | GitHub Release、不可变源码与签名资产 | 信笺只描述实际改动 |
| 世界设定 | `docs/worldbook.md` 与 `world_atlas.json` | 词典、统计及官网由脚本同步 |
| 授权与工程规则 | 用户指示、实际 AGENTS 链及 `.agents/` | 贡献与发布文档解释工程步骤 |
| 本地运行状态 | `.agent-runtime/` 摘要及原始回执 | 不发布日志、凭据、完整现场资料 |

发生冲突时保留原始出处并写清哪一项取代哪一项。旧日期更新、候选字样、Alpha 标题以及后来追加的小节都不能单独证明当前行为。

## 增量更新步骤

1. 核对实际版本与行为；将“实现”“验证”“已发布”和“未知”分开写。
2. 改最靠近拥有者的一份文档；新的当前能力同时更新能力总表，不复制整份说明。
3. 新文档在目录中登记层级、性质、主题和读取条件。公开路径需在 `.gitignore` 与 `scripts/repository_guard.py` 精确允许，不能放宽到整个 `docs/`。
4. 改生成物时更新源数据和脚本，重新生成，不手工补丁生成文档。
5. 核对相对链接、文件和命令，运行与变更相符的检查。提交精确文件，推送后核对 CI。

已发布信笺和历史报告保留原内容，历史索引可以补充它们的适用范围。当前专题中的版本小节只作演变记录；涉及新行为以能力总表和实际源码为准。

## 私有与公开分开维护

本地小说、生态完整稿、创作提纲、方案与运行证据原位保留，必要时在 `.agent-runtime/` 建立私有来源目录。本轮盘点不把私人稿件提交、复活为应用新章或提升为已采用设定。入口不链接本机绝对路径；公开源码包也不包含本地规则和工作记录。
