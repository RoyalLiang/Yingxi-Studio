# alpha.64 当前问题与播放风险检查

核对日期：2026-10-27。基线为 alpha.63（`2b6d5b8c2e71951a799b2eb205877cda2df1a348`），候选为 alpha.64 / 安装序号 66。范围是更新交互与安装、字幕设置、播放入口方向，以及与性能、解码、Surface 输出直接相关的链路；这次检查不代表所有模块都已穷尽审查。

## 本轮确认并修复的问题

| 问题 | 原因与调整 | 验证方式 |
| --- | --- | --- |
| 检查更新失败后还需点按钮读原因 | 原界面把错误藏在“查看更新提示”弹窗中。失败与后台下载错误改为顶部居中的短暂提示，保留完整文字和无障碍播报。 | 原更新界面的两项回归均失败；修复后的同场景通过，并检查真实截图。 |
| 下载时出现两个主要按钮 | 原页同时保留检查和下载按钮。页底改为一个当前操作；暂停、继续与安装由状态决定，重新检查保留在信笺更多菜单中。 | 可用更新、下载、暂停、错误状态的 Compose 断言。 |
| 自动安装前页面弹跳 | 原链路先启动应用内准备 Activity，再返回，随后由广播打开系统确认；同一安装包还重复校验。改为在设置页背后完成一次校验与安装会话创建，直接交给系统；同一个 ViewModel 拦截重复请求。 | 验证签名与摘要的原有边界保留；安装交接、会话数量与系统确认单独验证。Android 首次安装来源授权仍由系统完成。 |

| 设置名称与自定义字幕来源缺失 | 使用“信号采集频段”和“字幕驿站”；删除旧说明段，增加带 `{query}` 的搜索网址。自定义站只准备浏览器链接。 | 地址编码/校验单元测试、窄屏与 1.8 倍字号、自定义链接生成检查。 |

## 仍需关注的项目

| 优先级 | 项目 | 当前结论与影响 | 下一步证据 |
| --- | --- | --- | --- |
| P1 | 原始 4K Dolby Vision P5 的持续播放 | `MpvPlayer` 的兼容路线明确使用 `hwdec=no`，在 CPU 解码后执行 RPU/SDR 映射。高分辨率、高帧率或热降频可能造成掉帧、发热和耗电；这是代码路径支持的风险推断，本轮不能据模拟器认定 OnePlus 原片流畅。 | 同一原片在 OnePlus 上以 1× 持续播放，记录丢帧、音画差、温度、CPU/GPU 与读取耗时。 |
| P1 | 真机 HDR、色彩与 Surface 生命周期 | 兼容后端目标是 BT.709/sRGB SDR，不能当作原生 Dolby Vision HDR。系统 HDR 路线依赖屏幕、硬件解码器和固件；模拟器中的可见帧与 Surface 恢复不能证明物理屏幕的亮度、色彩与旋转后长期稳定性。 | 真机 HDR10/HLG/DV 同片对照，核对 decoder、输出 dataspace、可见画面与反复旋转。 |
| P2 | AV1 软件回退缺口 | 现有软件回退白名单没有开放 AV1；历史记录提到 ARM64 10-bit 路线的 SVE 指令崩溃，因此未把第三方库具备某编码器等同于应用可安全使用。设备系统不能解的 AV1 仍可能失败。 | 单独验证目标 ARM CPU 的库构建与 8/10-bit、film grain，再讨论开放回退。 |
| P2 | 首次打开未知方向的竖屏网络影片 | 既无缓存又未取到 tracks 时，无法零成本得知真实方向。本轮选择先横屏入场，收到实际属性后转为竖屏；第一次仍可能有一次方向调整。手动方向和锁定继续优先。 | 慢网、首次打开、清缓存、队列横竖交替与重新进入；不以文件名猜方向。 |
| P2 | 内存与远程读取负担 | Media3 的目标缓冲为 64 MiB；MPV 另有 64 MiB demux 缓冲和 DV 解码帧队列，再加解码器、纹理与图片缓存。它们不是应用内存上限。高码率读取、字幕/缩略图任务和进程热稳态需要真机测量。 | 连续播放、拖动、退后台与多次进入退出，比较 PSS、堆、读取时延和帧时序。 |
| P2 | 主线程同步落盘 | `UpdateDownloads.start → save` 在启动下载时同步 `SharedPreferences.commit()`；回执幂等标记也使用同步提交。持久性有实际用途，但慢存储上可能导致短时 UI 卡顿。本轮没有对这些路径取得卡顿采样，不能把它们定为本次视频等待的原因。 | 用 Perfetto/主线程栈确认延迟后，把耐久写入放到 IO 线程，并保留“落盘成功后才执行”的顺序。 |
| P2 | 格式能力说明的时间层次 | 旧格式报告保留了 alpha.55、alpha.57 等历史表格；例如早期 WMV 未接通的表述已被后续兼容接入覆盖。只读其中旧表会误判当前能力。 | 以当前路由、逐格式实际样片和本报告为当前证据，不把所有 FFmpeg 编码能力写成应用承诺。 |

## 解码和渲染链路检查

- `HdrRenderersFactory` 保持系统视频优先，软件 renderer 在受控失败后接管；`VideoDecoderRecovery` 区分视频 decoder 错误与网络、权限、音频错误。首帧看门狗要求已有排队媒体，避免把慢网直接当作 decoder 卡死。
- `PlaybackActivity` 的方向状态按片目更新，保留手动方向与锁定；`PlaybackOrientationProbe` 只调整入口等待策略，不更换播放器或解码库。
- `MpvPlayer` 的首帧、缓存状态与实际输出仍分别维护。正常前进的播放位置、`STATE_READY` 或未报错，都不能单独证明可见画面已持续输出。
- 新字幕搜索地址只允许不含账号密码的 HTTP(S) URL，片名独立编码；自定义站没有后台抓取或未经点击的浏览器跳转。

## 静态告警如何解读

本地 Lint 没有 error，但仍有既有 warning，不能称为“零告警”。`AliyunCloud`、`SealedMedia` 的四个静态 Context 告警对应 `applicationContext`，本次未发现它们持有 Activity；媒体服务虽导出，但 `onConnect` 拒绝不可信控制器，并限制系统/耳机可执行命令。依赖包 Bouncy Castle 的空 TrustManager 告警来自库内类，本次没有发现应用为 WebDAV/网盘安装该 TrustManager；它仍需按可达调用链继续审计，不能直接写成“应用信任所有证书”，也不能仅因来自依赖就视为已排除。

## 验证与范围

本地核心测试 139 项：134 通过、5 项因外部协议环境缺失跳过；Python 脚本 74 项通过。Android 16 模拟器统一回归 41 项通过，另有真实系统安装交接 1 项通过，完成同签名 alpha.63 → alpha.64 覆盖安装。旧更新界面的两项对照测试均失败，修复后通过。慢 WebDAV 夹具中的一次入口方向决策为 1 ms，这不是首帧时间或真实 NAS 启播耗时。提示淡出小幅调整后的六项设置专项与 R8 启动/设置烟测也通过；正式发布源码、CI、APK 摘要和对应安装证据记录在本任务交付记录中。合成样片检查与模拟器结果覆盖回归行为；用户 OnePlus 的实际固件、原始 4K P5、真实 NAS/网盘吞吐、长时间温控与物理 HDR 色彩仍是独立验收项。

本机文件系统会自动给文件附加 `com.apple.provenance`，一次去除尝试后仍存在，未反复清理或扩大范围；本地源目录/APK 条目未发现 `.DS_Store`、AppleDouble 或 `__MACOSX`。正式交付使用 Linux CI 生成的 APK 与源码归档，不能将归档条目合格写成本机无扩展属性。
